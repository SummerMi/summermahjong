# riichi 交付清单（2026-11-10）

> 单人天凤式日麻（1 真人 + 3 AI）——Go 多智能体对局服务。
> 本文是「面试前自检 / 工程验收」用的一页索引：做了什么、数字多少、怎么跑、边界在哪、材料在哪。

## 1. 一句话

用 Go 从零实现日麻的**规则引擎 + 对局服务 + 多智能体评测**：41 役种规则、事件溯源 + WebSocket 续传、13 个 AI 策略、固定 seed 可复现的 ELO 评测，外加把规则能力包装成 MCP 工具给 LLM 用。

## 2. 交付物

| 类别 | 内容 | 位置 |
|---|---|---|
| 规则引擎 | 41 役种、符/点数、振听/立直/食替、副露拆解（明暗刻） | `riichi/internal/rules/`（覆盖 96.2%） |

| 智能体 | 随机/向听/防守/搜索 × 3 打风 = 13 个工厂名 + 超时回退 | `riichi/internal/agent/`（93.7%） |

## 5. 怎么跑

```bash
cd riichi

# 1) 全量测试
go test ./... -count=1 -cover

# 2) 自对弈评测（产出 report.json / report.md / manifest.json）
go run ./cmd/riichi-eval --count 20 --calls=agent --out .tmp-eval

# 3) MCP 工具（stdio JSON-RPC）
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | go run ./cmd/riichi-mcp

# 4) 起服务 + 网页
go run ./cmd/riichi-server -addr 127.0.0.1:8099 -jwt-secret dev -issue-token 0
# 浏览器打开 web/index.html（file:// 即可，后端已默认开 CORS）
```

## 6. 已知限制（如实）

1. **策略层立直/鸣牌**：已能主动立直（13.4%–43.6%）并按「鸣后向听改善」选择性鸣牌；但鸣牌决策还没考虑役种价值与防守，attack 打风呈现高和了/高放铳画像（41.3% / 14.0%）；
2. **真 LLM 未接真 key**：`agent/llm` 支持 OpenAI 兼容接口，但测试与 demo 用 MockClient；真实成本/延迟未测；
3. **MySQL JSON 归一化**：事件 payload 存 JSON 列，读回语义相等、字面不保证相等（测试按语义比较）；
4. **-race 只在 CI 跑**：本机 Windows 缺 64-bit gcc；CI `riichi-test` job 覆盖；
5. **观战/多人**：只读观战已做（`?spectator=1`），跨实例观战镜像已做（共享 Redis store 回放 + `riichi:room:<id>` pub/sub 转发，两实例观战端事件逐条一致有测试）；座位动作跨实例转发、owner 注册表未做；当前仍是 1 真人 + 3 AI；
6. **CI 覆盖来得晚**：S12 才补 riichi 门禁，早期只有本地门禁；
7. **规则口径可配**：食替 `Ruleset.Kuikae` 三档（`KuikaeSame` 默认天凤 / `KuikaeSuji` / `KuikaeNone`）；立直后暗杠仅在不改变听牌时允许；
8. **策略层不主动立直**：规则层支持立直，S8 策略只输出打牌/副露，立直率为 0（评测数字会随策略补全变化）。
