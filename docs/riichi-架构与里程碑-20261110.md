# 日麻多智能体项目：架构与里程碑（2026-11-10）

> 目标：单人对三个 AI 打日麻（天凤式），同时作为「Go 后端 + Agent」方向的作品集项目。
> 本文件是执行依据；进度在文末表格维护。

## 1. 成功标准（可验收）

| 维度 | 门槛 |
|---|---|
| 规则正确性 | 役种 ≥ 30、符/点数 25+ 金标用例全过、振听/立直/食替用例全过 |
| 引擎质量 | Go 单测覆盖 ≥ 90%、属性测试（136 张守恒、点数守恒）全绿 |
| 对局完整性 | 半荘从东 1 打到终局（连庄/流局听牌料/トビ終了），事件回放逐字段一致 |
| 服务 | WS `last_seq` 续传 100% 补齐；200 并发建局 0 逃逸；非 LLM 决策 P95 < 20ms |
| Agent | 4 类策略 + 3 种打风；固定 seed 自对弈 1,000 局 → 指标表 + ELO |
| LLM | 候选重排模式，调用次数/成本可测；报告 vs 纯启发式的胜率/放铳率差 |

## 2. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 核心语言 | **Go 唯一真相**（规则 + 对局服务）；Python 只做 oracle 对拍与评测分析 | 目标岗是 Go；规则只实现一遍 |
| 旧 FastAPI | 冻结到 `legacy/v1-simplified/` | 避免两套对局服务互相拖累 |
| 状态管理 | 事件溯源 `state = fold(events)`，seed 决定牌山 | 回放/续传/评测复现一次解决 |
| Agent 信息 | 只给 `Observation`（可见信息），server 裁剪 | 防作弊结构性保证 |
| LLM | 只做高层：top-k 候选重排 + 解释 | 控成本、控延迟、可评测 |
| 传输 | WS 事件流 + `seq`/`last_seq` 续传 | 优于「推 state」 |
| 规则集 | 默认天鳳般（喰いタン有り、赤 5×3、切り番なし） | 与天凤体验一致 |

## 5. 测试策略

1. 单测：役种正/反例、符、25 手金标点数、振听/立直/食替。
2. 属性测试：随机合法对局 1,000 局，校验不变量（136 张、每类 ≤4、点数守恒、seq 单调）。
3. Oracle 对拍：Python `mahjong` 库生成「手牌+和牌/向听/点数」1 万例，Go 全量比对（复刻 v1 的 Go↔Python 对拍故事）。
4. 回放一致性：事件流 fold 出的状态 == 实时状态。
5. CI：`gofmt -l`、`go vet`、`go test -race`、覆盖率 ≥ 90%、20 局评测回归。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 规则 bug | 先 oracle 对拍 + 金标用例，规则层不接 UI/服务 |
| 前端膨胀 | 明确最小可用，时间盒 4 天，超时砍动画 |
| LLM 慢/贵/不稳 | top-5 候选重排 + 缓存 + 超时回退启发式 |
| 自对弈慢 | 纯函数规则 + 34 计数数组 + goroutine 并发评测 |
| 时间冲突 | M0–M2 先出可跑引擎（核心资产），服务/UI 可后置 |
