## 1. 方法

### 1.1 自对弈驱动（进程内，通用驱动）

```
game.NewWithOptions(seed, rules, {ManualResponses:true, ScoreProvider:RulesScorer})
loop 直到 PhaseGameEnd:
  AwaitDraw     → Apply(Legal()[0])                  # 摸牌；摸空=荒牌流局（引擎返回错误但状态已结算）
  AwaitDiscard  → agent.DecideWithTimeout(Observe(Turn), 500ms) → Apply
                  # 若合法动作里含自摸，驱动层强制取（能胡必胡）
  AwaitResponse → 对每个仍有 Responses 的座位问 agent（`--calls=agent`：吃碰杠荣和 pass 都交给 agent）
  RoundEnd      → tallyRound(本局新增事件) → StartNextRound()
```

关键点：

1. **不假设动作种类**：只从 `Observation.LegalActions` / `Observation.Responses` 里选，
   摸打、吃碰杠、立直、和了全部走同一条 `Apply` 路径。
2. **决策超时**：`agent.DecideWithContext`，默认 500ms（契约 §4），超时回退启发式首选。
3. **和了必取**：S8 内置策略只输出「打牌」动作，不会主动叫和；评测层把「能胡必胡」
   作为统一规则补上。
4. **可复现**：agent 的随机源由 `seed*4+seat` 派生，同 seed 同配置 → 同动作序列、同结果。
5. **异常记录**：某场驱动失败（引擎返回错误/非法状态）只记录 `games[].error` 并跳过该场，
   不中断整批评测。**本轮 20 场 0 异常**（上一轮的 seed 7 已在引擎侧修复）。

### 1.2 计分

默认注入 `eval.RulesScorer`（`game.Options.ScoreProvider` 的实现）：

- 把 `game.Meld` 转成 `rules.Meld` → `rules.Decompose(暗牌, 副露, 和了牌)` → `Evaluate`
  （役种/翻/符）→ 宝牌/赤宝牌/里宝牌加成 → `rules.Score` → 拆成四家净点数变化（总和为 0，
  本场计入，立直棒由引擎另加）；
- 门清、副露、暗杠、七对、国士都走真实规则（S5b `f37b275` 起 `Decompose` 支持副露）；
- 兜底：若引擎判和而 rules 拆不出/无役，回退 1 翻 30 符并在役种里标注「近似计分」。

### 1.3 指标与 ELO

| 指标 | 口径 |
|---|---|
| 和了率 / 放铳率 / 立直率 | 分子 / 该座位打过的轮数（分母为 0 时输出 `null`） |
| 副露/轮 | 副露/杠事件数 / 轮数，**计数型指标，可能 > 1**（本次 1.06–2.55 次/轮）；此时二项 CI 无定义，JSON 里 `ci_low/ci_high` 为 `null` |
| 平均顺位 | 每场半荘按最终点数排名（同分并列）后取均值；无有效场次时为 `null` |
| 平均打点 | 和了者收入（自摸为三家支付之和，含本场/立直棒）/ 和了次数；0 和了时为 `null` |
| 决策 P50/P95 | 单次 `Decide` 耗时（毫秒）；0 决策时为 `null` |
| 役满数 | 和了事件 payload 里 `han >= 13` 的次数（含数え役满） |
| 置信区间 | 比例：正态近似 `p ± 1.96·√(p(1-p)/n)`；均值：样本方差标准误；样本少时仅供参考 |
| ELO | 半荘最终点数两两比较（同分各 0.5）→ Bradley-Terry `p_i/(p_i+p_j)`，MM 迭代上限 200 轮，平移到均值 1500 |

### 1.4 报告鲁棒性（`c3e04b4` 修复）

`--calls=agent` 首跑时报 `json: unsupported value: NaN`：副露次数/轮可能 >1，
`NewRate` 的二项方差 `p(1-p)` 为负 → `sqrt` 得 `NaN`。修复：

- `Rate` / `MeanCI` / `DurationStat` 实现 `MarshalJSON`：**分母/样本为 0 → 整个指标 `null`**；
  计数型指标（>1）的 CI → `null`；任何非有限值（NaN/Inf）→ `null`；
- `BuildReport` / `Write` 额外 sanitize manifest、games、ELO 里的裸 float；
- ELO 转换处加 NaN/Inf 兜底；
- Markdown/CLI 对计数型指标显示为「N 次/轮」而不是百分比。

单测覆盖 0 局 / 0 和了 / 0 立直 / 0 决策 / 每轮副露 5 次五种边界，断言 JSON 可序列化且无 NaN/Inf。

## 4. 解读

1. **排序可信**：`random` 在所有维度垫底（0% 和了、24.8% 放铳、平均顺位 3.80），
   与「随机合法动作」预期一致；`defense:defense` 保持第一（和了率 32.1%、放铳率 9.6%），
   在允许副露的牌局里，防守打风权重开始体现价值。
2. **副露改变牌局形态**：`--calls=agent` 下平均每轮 8.1 次副露事件、93.2% 的和了来自副露手，
   牌局更快结束、荣和占比更高（146/192）。与更早的「禁鸣牌」20 场（230 轮、0 副露、181 和了）
   不可直接比较，差异主要来自鸣牌策略。
3. **置信区间**：20 场下和了率 CI 约 ±5~6 个百分点；`defense`(32.1%) 与 `search`(28.4%) 的
   区间仍重叠，不能断言显著差异；要下细结论需 ≥200 场。
4. **S8 策略仍不含立直/和了决策**：立直率恒为 0，和了由驱动层「能胡必胡」补上；
   当前评测更接近「摸打 + 鸣牌」策略对比，而不是完整日麻策略对比。

## 5. 已知限制与原因（诚实口径）

1. **响应窗口 `--calls=agent` 已真实生效**：S5b 集成后「吃/碰后打牌」已接通，本批
   20 场共 1757 次副露/杠事件、93.2% 的和了是副露和了，说明鸣牌路径确实跑通了。
2. **立直率 ≈ 0**：S8 的 `shanten` / `defense` / `search` 只输出 `ActDiscard`，不会选
   `ActRiichi`；评测层不代打立直，避免把策略能力和驱动补丁混在一起。S8 支持后该指标自动生效。
3. **seed 7 的引擎边界 —— 已修复（d61a7fb）**：上一轮该场在座位 0「4 组副露 + 手牌 2 张、
   吃 5m 后食替禁则把两张手牌全禁」时 `Legal()` 为空，只能 aborted。api-platform 在
   **d61a7fb** 给引擎加了「副露后是否还有可打牌」的前瞻（食替禁满的吃/碰不再生成选项）；
   本轮复测 seed 7 **正常打满 9 局**、全批 **0 aborted / 0 error**。该修复在 `internal/game`，
   属引擎侧。
4. **样本量**：20 场 / 218 轮，CI 较宽；默认 `--seeds 1-100` 可扩到 100 场，
   完整 1000 局出图属于里程碑 M5 的后续工作。
5. **计分兜底**：引擎判和但 rules 拆不出/无役时回退 1 翻 30 符（事件 yaku 带「近似计分」）；
   本批未触发。
6. **未接入**：`Replay` 校验、store 落库、图表输出（目前 report.md 表格 + report.json 原始数据）。
